# Changelog

## v2.8.0 — 2026-09-28

Модернізація за результатами аудиту 2026-09-27. Усі 9 підтверджених проблем закрито. 23 коміти, 108 тестів (було 95).

### 🧹 Гігієна репозиторію

- Видалено `legacy/` (~21 000 рядків застарілого GUI); точка відкату — тег `v2.7.0-pre-cleanup`
- Запуск зведено до єдиної точки входу `main_pyside6.py`; мертві лаунчери, демо й скрипти видалено
- Видалено сміттєві файли (файли-«привиди», патчі, бінарники, демо-CSV — у `.gitignore`)
- Завершено консолідацію моделей: `ventilation_company/models/` повністю видалено, канонічний шар — `database/models/`
- Прибрано мертві посилання на `legacy/` з конфігів ruff/black/pytest

### ⚙️ Конфігурація і бізнес-дані

- Хардкод цін/ставок винесено з `config.py` у `data/business_settings.json` та `data/pricing_settings.json`
- Нова вкладка «Налаштування → Бізнес»: ПДВ, ціни на комплектуючі та ізоляцію, посади/ставки, фланці (admin/director)
- `CostEngine` підключено до `BusinessSettings` (ПДВ і ціни фланців беруться з налаштувань)
- Лінива ініціалізація engine БД: немає side-effect на імпорті, неналаштований `DATABASE_URL` дає зрозумілу помилку з інструкцією
- Залежності: один драйвер `psycopg[binary]`, опційні пакети (3D, AutoCAD, вебв'ю) — у `requirements-optional.txt` із graceful-degradation

### 🔧 Стабільність і типи

- Розірвано циклічний імпорт `calculations` ↔ `services` (ліниві пакети)
- mypy поширено на весь пакет + `--check-untyped-defs` (383 помилки типів виправлено), додано в CI-ґейт
- Стабілізовано життєвий цикл GUI worker thread у тестах/CI
- Асинхронне завантаження карток проєктів та CRM-клієнтів через `FunctionWorker` (UI не блокується)

### ✅ Якість і CI

- Живий E2E-сценарій (логін → проєкт → виріб → PDF → аудит) зі справжнім PostgreSQL — окремий CI-job
- Qt runtime-залежності для headless PySide6 на Linux у CI
- Фікс: glob у зборі файлів бекапу повертає ітератор, а не set
- Синхронізовано `__version__` у всіх місцях (`version.py` — єдине джерело істини)

### 📖 Документація

- README повністю переписано й звірено з реальним станом: схема БД (32/32 таблиці), ролі, структура, лічильники
- Документацію звірено з кодом: `docs/USER_GUIDE.md`, `INSTRUCTION.md` відповідають реальному функціоналу
